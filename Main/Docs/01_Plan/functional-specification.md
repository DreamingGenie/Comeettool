# 기능 명세서 (Functional Specification)

> 📌 **공동 편집 안내.** 이 문서는 노션에서 팀이 함께 편집한다. 각 기능은 리스트 항목으로 관리하며,
> 우선순위는 항목 끝의 배지(`MVP` / `SUB` / `Extra` / `TBD`)로 표기한다. 의견·논의가 필요하면
> 해당 항목 아래에 하위 불릿으로 코멘트를 남긴다.

## 1. 개요 및 용어

### 1.1 서비스 개요
실시간 화상회의를 중심으로 팀 협업을 지원하는 플랫폼이다. 팀 스페이스 단위로 멤버가 모여 화상회의를 진행하고, 회의 중 실시간 채팅과 Markdown 문서 공동 편집을 수행하며, 회의 종료 후 AI가 회의록을 자동 생성한다.

### 1.2 용어 정의
- **팀 스페이스(Team Space)** — 멤버·회의·문서·일정이 소속되는 협업 단위
- **회의(Meeting)** — 팀 스페이스 내에서 생성되는 화상회의 세션
- **호스트(Host)** — 회의를 시작·종료하고 참여자를 관리하는 권한 보유자
- **SFU** — Selective Forwarding Unit. 참여자별 미디어 트랙을 서버가 선택적으로 중계하는 미디어 서버 구조
- **회의록** — 회의 종료 후 전사·채팅·공동 문서를 기반으로 AI가 생성하는 정리 문서

### 1.3 우선순위 범례
- **MVP** — 1차 필수 구현
- **SUB** — MVP 이후 구현
- **Extra** — 여력이 있을 때 구현하는 부가 기능
- **TBD** — 우선순위/포함 여부 미정 (팀 논의 필요)

## 2. 사용자 및 인증 (AUTH)

- **AUTH-01 회원가입** `MVP` — 이메일과 비밀번호로 계정을 생성한다
- **AUTH-02 로그인** `MVP` — 인증 후 Access/Refresh Token을 발급한다
- **AUTH-03 토큰 갱신** `MVP` — Refresh Token으로 Access Token을 재발급한다
- **AUTH-04 로그아웃** `MVP` — Refresh Token을 폐기하여 세션을 종료한다
- **AUTH-05 기본 프로필 조회** `MVP` — 닉네임과 프로필 이미지를 조회한다
- **AUTH-06 기본 프로필 수정** `MVP` — 닉네임과 프로필 이미지를 수정한다
- **AUTH-07 비밀번호 변경** `MVP` — 기존 비밀번호 확인 후 변경한다
- **AUTH-08 회원 탈퇴** `MVP` — 서비스에서 회원 탈퇴한다
- **AUTH-09 비밀번호 재설정** `SUB` — 이메일 인증으로 비밀번호를 재설정한다
- **AUTH-10 사용자 검색** `MVP` — 이름 또는 이메일로 사용자를 검색한다

> **Note.** AUTH-09는 이메일 발송 인프라가 필요하므로 일정이 촉박하면 뒤로 미룰 수 있다.
> **Note.** 프로필 이미지 등 콘텐츠는 오브젝트 스토리지에 저장하고 DB에는 URL/메타데이터만 보관한다.
> **Note.** AUTH-10 사용자 검색은 멤버 초대(MEMBER-02)에서 대상을 찾는 용도로 쓰인다.

## 3. 팀 스페이스 (Team Space)

### 3.1 팀 스페이스 목록 관리 (SPACE)

- **SPACE-01 팀 스페이스 생성** `MVP` — 이름·설명·설정으로 팀 스페이스를 생성한다 (생성 후 멤버에게 초대 발송)
- **SPACE-02 팀 스페이스 목록** `MVP` — 참여 중/참여 가능한 팀 스페이스를 조회한다 (참여 가능 = 초대 수락 대기)
- **SPACE-03 팀 스페이스 검색** `Extra` — 팀 스페이스를 검색한다
- **SPACE-04 팀 스페이스 정렬** `Extra` — 팀 스페이스를 최신순·이름순으로 정렬한다

### 3.2 팀 스페이스 관리 (SPACE)

- **SPACE-05 팀 스페이스 상세보기** `MVP` — 정보·참여자·이력을 조회한다
- **SPACE-06 사이드바** `MVP` — 일정·멤버·회의·문서·설정 진입 내비게이션
- **SPACE-07 팀 스페이스 나가기** `MVP` — 참여자가 팀 스페이스에서 퇴장한다
- **SPACE-08 팀 스페이스 정보 수정** `Extra` — 이름·설명·설정을 변경한다 (Owner 권한)
- **SPACE-09 팀 스페이스 공유** `MVP` — 초대 링크/코드를 생성·공유한다 (게스트 초대 링크 포함)
- **SPACE-10 팀 스페이스 접근 제한** `Extra` — 비공개·비밀번호·초대자 전용 등 정책을 설정한다
- **SPACE-11 팀 스페이스 삭제** `MVP` — Owner가 팀 스페이스를 삭제한다
- **SPACE-12 팀 스페이스 채팅** `Extra` — 회의 외부에서 팀 대화를 지속한다 (CHAT-06과 동일 범위)

### 3.3 멤버 및 권한 (MEMBER)

권한은 MVP에서 지나치게 세분화하지 않는다. `Maintainer`는 Owner와 구분되는 권한이 확정될 때 추가한다.

| 역할 | 권한 |
| --- | --- |
| Owner | 스페이스 수정, 초대, 강퇴, 권한 변경, 회의 관리 |
| Member | 회의 생성·참여, 문서 편집, 회의록 조회 |
| Guest | 초대된 회의 참여 및 허용된 문서 열람 |

- **MEMBER-01 멤버 조회** `MVP` — 스페이스 소속 멤버와 권한을 조회한다
- **MEMBER-02 멤버 초대** `MVP` — Owner가 닉네임이나 이름을 조회해서 멤버를 초대한다
- **MEMBER-03 초대 수락** `MVP` — 사용자가 초대를 수락 처리한다
- **MEMBER-04 초대 거절** `MVP` — 사용자가 초대를 거절 처리한다
- **MEMBER-05 멤버 강퇴** `MVP` — Owner가 멤버를 스페이스에서 제외한다
- **MEMBER-06 권한 변경** `MVP` — Owner가 멤버의 권한을 변경한다
- **MEMBER-07 스페이스 프로필** `MVP` — 스페이스별 닉네임·직무(예: 백엔드, PM)를 설정한다

> **Note.** 게스트 초대 링크 생성은 별도 기능으로 두지 않고 SPACE-09(팀 스페이스 공유)로 통합한다.

## 4. 일정 (SCHEDULE)

- **SCHEDULE-01 내 일정 일괄 확인** `SUB` — 팀 스페이스와 무관하게 내게 할당된 일정을 한 번에 확인한다
- **SCHEDULE-02 팀 일정 목록 조회** `SUB` — 캘린더(월·주·일)에서 팀 일정을 확인한다 (사이드바/일정 페이지)
- **SCHEDULE-03 일정 생성** `SUB` — 캘린더에서 일정을 생성한다
- **SCHEDULE-04 일정 수정** `SUB` — 일정의 시간·멤버 등을 수정한다
- **SCHEDULE-05 일정 삭제** `SUB` — 캘린더에서 일정을 삭제한다

> **Note.** 일정에는 담당자·마감일을 지정하고 회의·회의록과 연결할 수 있다.
> **Note.** AI가 일정을 직접 등록하지 않고 `후보 추출 → 사용자 검토 → 확정` 흐름을 적용한다. 중복 일정은 경고한다.

## 5. 화상회의 (MEET / RTC)

### 5.1 회의 생명주기 (MEET)

- **MEET-01 회의 생성** `MVP` — 스페이스 내에 회의를 생성한다
- **MEET-02 회의 목록** `MVP` — 진행 중인 회의를 조회한다
- **MEET-03 회의 입장** `MVP` — 권한이 있는 사용자가 회의에 입장한다
- **MEET-04 회의 퇴장** `MVP` — 권한이 있는 사용자가 회의에서 퇴장한다
- **MEET-05 회의 종료** `MVP` — 호스트가 모든 참여자의 회의를 종료한다
- **MEET-06 참여자 조회** `MVP` — 현재 접속자와 마이크·카메라 상태를 확인한다
- **MEET-07 참여자 강퇴** `MVP` — 호스트가 특정 참여자를 퇴장시킨다

> **Note.** 회의 생성이 곧 시작을 겸한다(별도 "회의 시작"은 두지 않음 — 생성과 중복). **진행 중인 회의만 관리**하며, 예정·과거 회의는 캘린더(§4 SCHEDULE)에서 일정으로 확인한다.

### 5.2 실시간 미디어 (RTC)

- **RTC-01 영상·음성 송수신** `MVP` — 참여자가 실시간 미디어를 송수신한다
- **RTC-02 장치 선택** `MVP` — 카메라·마이크·스피커를 선택한다
- **RTC-03 카메라·마이크 제어** `MVP` — 자신의 카메라·마이크를 켜거나 끈다
- **RTC-04 기본 화면 배치** `MVP` — 참여자 영상을 그리드로 표시한다
- **RTC-05 발언자 표시** `SUB` — 음성 레벨에 따라 현재 발언자를 강조한다
- **RTC-06 화면 공유 시작** `SUB` — 화면 공유를 시작한다
- **RTC-07 화면 공유 종료** `SUB` — 화면 공유를 종료한다
- **RTC-08 영상 녹화** `SUB` — 회의 영상을 녹화한다
- **RTC-09 세부 세션** `Extra` — 참여자를 소규모 세션으로 분리한다

> **Note.** 부하 처리·녹화·다자 회의를 고려하여 미디어 전송은 **SFU 구조**를 사용한다 (§11, 결정 2).

## 6. 회의 채팅 (CHAT)

- **CHAT-01 메시지 송수신** `MVP` — 같은 회의의 참여자들이 메시지를 주고받는다
- **CHAT-02 채팅 내역 저장** `MVP` — 회의 종료 후 채팅을 다시 조회한다
- **CHAT-03 메시지 시간 표시** `MVP` — 메시지의 작성자와 작성 시간을 표시한다
- **CHAT-04 파일 첨부** `SUB` — 채팅에 파일을 첨부한다
- **CHAT-05 DM** `Extra` — 특정 참여자에게 개인 메시지를 전송한다
- **CHAT-06 스페이스 채팅** `Extra` — 회의 외부에서 팀 대화를 지속한다

## 7. 실시간 Markdown 문서 (DOC)

- **DOC-01 문서 생성** `MVP` — Markdown 문서를 생성한다
- **DOC-02 동시 편집** `MVP` — 여러 참여자가 같은 문서를 실시간 편집한다
- **DOC-03 참여자 표시** `MVP` — 편집 중인 사용자의 커서/선택 영역을 표시한다
- **DOC-04 자동 저장** `MVP` — 편집 결과를 주기적으로 저장한다
- **DOC-05 문서 조회** `MVP` — 문서를 조회한다
- **DOC-06 편집 권한** `MVP` — 호스트가 참여자의 열람·편집 권한을 설정한다
- **DOC-07 Markdown 내보내기** `SUB` — 문서를 `.md` 파일로 내보낸다
- **DOC-08 버전 복원** `SUB` — 자동 저장된 이전 버전으로 문서를 복원한다

> **Note.** 문서는 **회의에 종속되지 않고 독립적으로 운용**한다. 별도 스냅샷 저장 없이 자동 저장(DOC-04)만 두고, 복원(DOC-08)도 자동 저장된 버전을 사용한다.
> **Note.** 동시 편집은 CRDT(예: Yjs) 기반 동기화가 필요하며, 화이트보드(§9)도 동일 동기화 계층을 재사용할 수 있다.

## 8. AI 회의록 (AI)

- **AI-01 오디오 수집** `MVP` — 참여자별 오디오를 회의·사용자 정보와 연결해 저장한다
- **AI-02 발화 구간 검출** `MVP` — 침묵과 발화 구간을 구분한다
- **AI-03 음성 전사** `MVP` — 음성을 텍스트로 변환한다 (STT)
- **AI-04 화자·시간 연결** `MVP` — 발언에 사용자와 시작·종료 시간을 부여한다
- **AI-05 회의 요약** `MVP` — 전사·채팅·공동 문서를 기반으로 회의를 요약한다
- **AI-06 항목 추출** `MVP` — 안건·결정 사항·미결 사항·후속 작업을 추출한다
- **AI-07 회의록 생성** `MVP` — 회의 종료 후 정해진 템플릿으로 회의록을 작성한다
- **AI-08 회의록 조회** `MVP` — 생성된 회의록을 조회한다
- **AI-09 회의록 수정** `MVP` — 사용자가 AI 결과를 수정한다
- **AI-10 회의록 확정** `MVP` — 사용자가 AI 결과를 최종 확정한다
- **AI-11 생성 상태 표시** `MVP` — 대기·처리 중·완료·실패 상태를 표시하고 재시도한다
- **AI-12 회의 피드백** `SUB` — 참여도·논점 이탈 등 회의 진행을 분석한다
- **AI-13 실시간 발언 피드백** `Extra` — 스트리밍으로 들어오는 발언과 사용자 로그를 분석해 실시간 피드백을 부여한다

> **Note.** SFU에서 사용자별 오디오 트랙을 분리하므로, 전통적 화자 분리(diarization)가 아니라 **참여자별 트랙 식별 및 타임스탬프 정렬**로 구현한다.

## 10. 비기능 요구사항 (NFR)

- **회의 규모** — 회의실당 최대 인원 (§11, 결정 1 참조)
- **동시 처리** — 동시 회의실 수 제한 (§11, 결정 1 참조)
- **미디어 품질** — 기본 720p, 네트워크 상태에 따른 자동 조절
- **입장 시간** — 입장 요청 후 5초 이내 미디어 연결
- **문서 동기화** — 정상 네트워크에서 변경사항 500ms 이내 반영
- **자동 저장** — 5초 이내 서버 반영
- **회의록 처리** — 60분 회의 기준 종료 후 10분 이내 생성
- **장애 복구** — 일시적 연결 중단 후 자동 재접속
- **권한** — 스페이스·회의·문서 단위 접근 검사
- **개인정보** — 녹음 전 동의, 보관 기간 및 삭제 정책 제공
- **보안** — 비밀번호 해시, TLS, 저장 데이터 암호화
- **관측성** — 접속 실패·미디어 품질·AI 처리 실패 로깅

## 11. 확정된 정책 결정사항

1. **최대 회의 인원 / 동시 회의실 수** — 최대 회의 인원 **10명**, 팀 스페이스당 동시 회의실 **최대 3개**
2. **Mesh vs SFU** — **SFU 사용 확정**
3. **AI 음성 처리 시점** — **회의 후 처리** (종료 버튼으로 회의 종료 직후)
4. **음성 원본 보관 기간 / 동의 방식** — 보관 기간 **5년**(임의 설정), 녹음 전 사용자 동의
5. **회의 생성자 vs 진행자 권한** — **회의 Host가 권한을 보유**
6. **회의 종료 후 문서 편집 흐름** — AI 회의록 작성 → 팀 스페이스 Owner 컨펌 → 최종 AI 확정
7. **AI 회의록 템플릿 / 필수 출력 필드** — 부록 A·B 참조 (컨설턴트·코치 품질 검증 예정)
8. **게스트 회원가입 필요 여부** — **회원가입 필요**
9. **AI 작업 실패 재시도 정책** — LangGraph 검증 노드에서 자체 품질 검사 → 미달 시 **최대 3회 재작성**, 품질 검사 정책 별도 기재, 실패 시 알림
10. **팀 스페이스 정렬 정책** — 정렬 시 커스텀 정책을 적용한다
11. **공유 문서당 동시 편집 인원** — **10명**
12. **회의 종료 후 녹음 파일 저장** — 회의 종료 시 녹음 파일을 저장한다
13. **화자 분리 후 기록본 매핑** — 화자 분리 후 기록본을 매핑하고 타임스탬프를 부여한다
14. **오프라인 문서 작성** — 오프라인 문서 작성은 지원하지 않는다

## 부록 C. ID 정리 이력 (금번)

노션에서 기능 내용이 대규모로 수정되며 ID가 중복·공백된 것을 도메인별로 유일·연속되게 재정리했다.
**기능의 의미·범위·우선순위는 노션(원천)을 그대로 따르되, 번호와 명백한 오기만 조정**했다.

| 도메인 | 조정 내용 |
| --- | --- |
| AUTH | `AUTH-05` 중복(조회/수정) → `05 조회` / `06 수정`으로 분리, 이후 번호 순차 이동(비밀번호 변경 07, 회원 탈퇴 08, 재설정 09, 이름 검색 10, 이메일 검색 11) |
| SPACE | `SPACE-11 삭제` 설명 오기("검색·정렬한다") → "삭제한다"로 수정 |
| SCHEDULE | 별도 도메인(§4)으로 승격. `SCHEDULE-04` 중복(수정/삭제) → `04 수정` / `05 삭제`로 분리 |
| MEET | `MEET-04 회의 시작` 삭제 확정(생성과 중복). 진행 중인 회의만 관리, 예정·과거는 캘린더 확인 |
| DOC | `DOC-05 스냅샷 저장` 삭제 확정(문서 독립 운용·자동저장으로 충분). 이후 번호를 당겨 연속화, 복원은 자동저장 버전 사용 |
| AI | `AI 원문 근거 조회` 삭제 확정 + `AI-09` 중복(수정/확정) → 수정 08 / 확정 09로 정리. 부록 B의 `related_utterances`·`source_utterance` 필드 제거 |
| 섹션 | `§4`가 일정·화상회의에 중복 지정 → 일정 §4, 화상회의 §5로 분리. 이후 섹션 번호 순차 이동 |
| AUTH (2차·인벤토리 반영) | `AUTH-10 이름`·`AUTH-11 이메일` 검색 → `AUTH-10 사용자 검색` 하나로 통합 |
| MEMBER (2차·인벤토리 반영) | `MEMBER-02 초대 링크 생성` 삭제(SPACE-09로 통합) → 이후 번호 당김(초대 02 … 프로필 07) |
| AI (2차·인벤토리 반영) | `AI-08 회의록 조회` 신설 → 이후 번호 이동(수정 09, 확정 10, 상태 11, 피드백 12, 실시간 13) |

## 부록 D. 확정 결과 (이전 "누락 의심" 검토 완료)

| # | 항목 | 결정 |
