# CoMeetTool 시연 시나리오

## 1. 시연 목적

이 문서는 CoMeetTool의 핵심 사용자 흐름을 실제 배포 화면에서 재현하기 위한 발표자용 시나리오다.

```text
회원가입 → 로그인 → 팀 스페이스 생성 → 멤버 초대 → 회의 생성
→ 공유 문서 실시간 편집 → 회의 종료 → AI 산출물 확인
```

예상 소요 시간은 AI 처리 대기 시간을 제외하고 약 10~15분이다.

## 2. 시연 환경과 역할

### 2.1 브라우저 구성

동시 편집과 초대 수락을 보여주기 위해 로그인 세션을 두 개 준비한다.

| 구분 | 역할 | 권장 실행 환경 |
| --- | --- | --- |
| 브라우저 A | 팀 스페이스 OWNER, 회의 호스트, 발표자가 주로 조작 | Chrome 일반 창 |
| 브라우저 B | 초대받는 MEMBER, 회의 참가자, 공동 편집자 | Chrome 시크릿 창 또는 다른 브라우저 |

두 창은 한 화면에 나란히 배치하거나 서로 다른 컴퓨터에서 실행한다. 같은 브라우저의 일반 탭 두 개는 로그인 저장소를 공유하므로 서로 다른 계정을 동시에 유지하기 어렵다.

### 2.2 사전 점검

- Frontend 주소에 HTTPS로 접속할 수 있어야 한다.
- Backend health, Yjs WebSocket, LiveKit, AI 서비스가 정상이어야 한다.
- 배포된 Frontend는 `VITE_USE_MOCK_API=false`로 빌드되어야 한다.
- 브라우저의 마이크·카메라 권한 요청을 허용하고 PiP 지원 여부를 확인한다.
- 브라우저 B에서 사용할 MEMBER 계정은 시연 전에 회원가입과 최초 온보딩을 끝내 둔다.
- OWNER와 MEMBER는 서로 다른 이메일을 사용한다.
- AI 처리를 확인하려면 회의 중 실제 음성 발화와 VAD 녹음 업로드가 발생해야 한다.
- 네트워크가 안정적인 환경에서 진행하고 노트북 절전 모드를 해제한다.

### 2.3 시연용 입력값 예시

실제 비밀번호나 개인 이메일은 이 문서에 기록하지 않는다.

| 항목 | 예시 |
| --- | --- |
| OWNER 이메일 | `<시연용 OWNER 이메일>` |
| OWNER 비밀번호 | `<시연용 비밀번호>` |
| MEMBER 이메일 | `<사전 가입된 MEMBER 이메일>` |
| 팀 스페이스 이름 | `CoMeetTool 시연팀` |
| 팀 스페이스 설명 | `실시간 협업과 AI 회의 분석 기능을 검증하는 팀입니다.` |
| 회의 이름 | `MVP 기능 검토 회의` |
| 공유 문서 제목 | `MVP 기능 검토 안건` |

회원가입부터 반복 시연해야 한다면 이메일에 날짜나 회차를 포함해 중복을 피한다.

## 3. 상세 시연 순서

### 3.1 회원가입

#### 시작 화면

- 조작 창: 브라우저 A
- 시작 주소: Frontend 루트(`/`)
- 정상 화면: CoMeetTool 소개 화면

#### 실행 순서

1. 소개 화면에서 `로그인` 버튼을 클릭한다.
2. 로그인 카드 하단의 `회원가입`을 클릭한다.
3. `회원가입` 화면에서 다음 값을 입력한다.
   - `이메일 주소`: 시연용 OWNER 이메일
   - `비밀번호`: 시연용 비밀번호
   - `비밀번호 확인`: 동일한 비밀번호
4. `회원가입 →` 버튼을 클릭한다.

#### 입력 조건

- 비밀번호 길이는 8~20자다.
- 영문, 숫자, 특수문자를 각각 하나 이상 포함한다.
- 사용할 수 있는 특수문자는 화면 검증 기준 `!@#$%^&*()_+=-`다.

#### 정상 확인

- 별도 오류 메시지 없이 `/login`으로 이동한다.
- 이메일 중복 오류가 나오면 사용하지 않은 이메일로 다시 진행한다.

#### 발표 설명 예시

> 사용자는 이메일과 보안 조건을 만족하는 비밀번호만으로 계정을 생성할 수 있습니다. 회원가입이 완료되면 별도의 자동 로그인 없이 로그인 화면으로 이동합니다.

### 3.2 로그인 및 최초 온보딩

#### 실행 순서

1. `로그인` 화면에서 방금 가입한 OWNER 이메일과 비밀번호를 입력한다.
2. `로그인 →` 버튼을 클릭한다.
3. 신규 계정이면 `/onboarding` 화면이 나타나는 것을 확인한다.
4. 이번 시연에서는 빠른 진행을 위해 화면 왼쪽 아래의 `나중에 하기`를 클릭한다.
5. `/home` 대시보드로 이동한다.

온보딩 자체를 보여줄 경우 직군, 세부 직무, 연령대, 성별을 순서대로 선택한 뒤 마지막 단계에서 `시작 →`을 클릭한다.

#### 정상 확인

- 왼쪽에는 `MY WORKSPACES`, 중앙에는 `회의 바로가기`와 `나의 일정`이 표시된다.
- 상단 사용자 영역과 초대 알림 버튼이 표시된다.

#### 발표 설명 예시

> 로그인 후 최초 사용자에게는 맞춤형 협업 환경을 위한 온보딩을 제공합니다. 온보딩은 나중에 진행할 수도 있으며, 로그인 세션은 Access Token과 Refresh Token 흐름으로 유지됩니다.

### 3.3 팀 스페이스 생성

#### 실행 순서

1. `/home` 왼쪽 `MY WORKSPACES` 목록의 가장 아래에 있는 `+` 버튼을 클릭한다.
   - 접근성 이름은 `새 팀 스페이스 만들기`다.
2. `새 팀 스페이스` 모달에서 다음 항목을 설정한다.
   - `팀 프로필 이미지`: 선택 사항
   - `팀 이름`: `CoMeetTool 시연팀`
   - `설명`: 준비한 시연 설명
   - `팀 색상`: 원하는 색상
3. 모달 아래의 `팀 스페이스 만들기`를 클릭한다.
4. 왼쪽 `MY WORKSPACES` 목록에서 생성한 팀 스페이스를 클릭한다.

#### 정상 확인

- `팀 스페이스를 만들었습니다.` 알림이 나타난다.
- 이미지를 함께 등록했다면 `팀 스페이스와 프로필 이미지를 등록했습니다.`가 나타난다.
- 팀 화면 왼쪽 메뉴에 `일정`, `공유 문서`, `회의록`, `AI 요약`, `AI 피드백`, `멤버`, `설정`이 표시된다.
- 생성한 계정의 권한은 OWNER로 표시된다.

#### 발표 설명 예시

> 팀 스페이스는 일정, 문서, 회의와 AI 산출물을 묶는 협업 단위입니다. 생성자는 OWNER가 되며 팀 프로필 이미지와 대표 색상을 설정할 수 있습니다.

### 3.4 멤버 초대 및 수락

#### OWNER가 초대 발송

1. 브라우저 A의 팀 왼쪽 메뉴에서 `멤버`를 클릭한다.
2. `팀 멤버` 화면 오른쪽 위의 `＋ 멤버 초대`를 클릭한다.
3. `멤버 초대 및 공유` 모달의 `이름 또는 이메일` 입력란에 MEMBER 이메일을 두 글자 이상 입력한다.
4. 아래에 표시된 검색 결과에서 MEMBER 사용자를 클릭한다.
   - 이메일을 입력만 해서는 초대할 수 없으며 반드시 검색 결과를 선택해야 한다.
5. `초대 발송`을 클릭한다.

#### MEMBER가 초대 수락

1. 브라우저 B에서 사전에 준비한 MEMBER 계정으로 로그인한다.
2. 화면 오른쪽 위의 종 모양 `초대 알림` 버튼을 클릭한다.
3. `초대 알림` 목록에서 `CoMeetTool 시연팀` 초대를 찾는다.
4. `수락`을 클릭한다.
5. 필요하면 `새로고침`을 눌러 초대 상태를 다시 불러온다.
6. 브라우저 B의 팀 목록에서 `CoMeetTool 시연팀`을 클릭한다.

#### 정상 확인

- 브라우저 A에는 `OOO님에게 초대를 보냈습니다.` 알림이 나타난다.
- 브라우저 B에서 초대 수락 후 해당 팀 스페이스에 접근할 수 있다.
- 브라우저 A의 `멤버` 화면을 다시 열거나 새로고침하면 OWNER와 MEMBER가 함께 표시된다.
- 초대받은 사용자의 기본 권한은 MEMBER다.

#### 발표 설명 예시

> OWNER는 이미 가입한 사용자를 이름이나 이메일로 검색해 초대할 수 있습니다. 초대받은 사용자는 알림에서 수락하며 기본적으로 MEMBER 권한을 부여받습니다.

### 3.5 회의 생성 및 MEMBER 입장

#### OWNER가 회의 생성

1. 브라우저 A의 왼쪽 메뉴에서 `일정`을 클릭한다.
2. `진행 중인 회의` 영역의 `새 회의 만들기` 카드를 클릭한다.
3. `회의 생성하기` 모달에서 `회의 이름`에 `MVP 기능 검토 회의`를 입력한다.
4. 팀 화면에서 생성했으므로 `담당 팀`이 현재 팀으로 고정된 것을 확인한다.
5. `회의 만들기`를 클릭한다.
6. 브라우저의 마이크와 카메라 권한 요청을 허용한다.

회의 생성이 성공하면 별도의 목록 단계를 거치지 않고 `/meetings/{meetingId}` 회의 화면으로 바로 이동한다.

#### MEMBER가 회의 입장

1. 브라우저 B에서 팀 스페이스의 `일정` 화면을 연다.
2. `진행 중인 회의` 카드에서 `회의 입장 →`을 클릭한다.
3. 또는 오른쪽 위 알림에 회의 초대가 있으면 `바로 참가하기`를 클릭한다.
4. 마이크와 카메라 권한을 허용한다.

#### 정상 확인

- 두 브라우저 모두 회의 제목과 `연결됨` 상태를 확인한다.
- 오른쪽 위 참가자 수가 2명으로 표시된다.
- 참가자 화면과 마이크·카메라 상태가 서로 반영된다.
- 발화하면 발화자 화면 강조와 VAD 감지가 동작한다.

#### 발표 설명 예시

> 회의는 팀 스페이스 안에서 즉시 생성되며 LiveKit을 통해 참가자 영상, 음성, 채팅과 화면 공유를 제공합니다. 음성은 VAD 기반으로 발화 구간만 분리해 후속 AI 처리에 사용합니다.

### 3.6 회의 중 공유 문서 실시간 편집

#### 문서 열기

1. 브라우저 A 회의 화면 아래의 제어 영역에서 `문서`를 클릭한다.
2. 회의 영상이 PiP로 전환되고 팀의 `공유 문서` 목록으로 이동하는 것을 확인한다.
3. 화면 오른쪽 위의 `＋ 새 문서`를 클릭한다.
4. 새 문서가 생성되면서 편집 화면으로 바로 이동한다.

브라우저가 PiP를 지원하지 않거나 권한을 차단하면 문서 전환이 제한될 수 있으므로 시연 전 Chrome에서 반드시 확인한다.

#### 제목과 본문 편집

1. 제목 영역의 기본값 `새 문서`를 클릭하고 `MVP 기능 검토 안건`으로 변경한다.
2. 본문 `문서 내용을 입력하세요.` 영역을 클릭한다.
3. 다음과 같은 안건을 입력한다.

```text
1. 핵심 사용자 문제 확인
2. MVP 기능 범위 확정
3. 담당자 및 다음 일정 결정
```

#### 동시 편집 확인

1. 브라우저 B에서도 회의 화면 아래 `문서`를 클릭한다.
2. 공유 문서 목록에서 `MVP 기능 검토 안건` 행 또는 `열기 →`를 클릭한다.
3. 브라우저 A와 B에서 서로 다른 문장이나 목록 항목을 동시에 입력한다.
4. 편집 화면 오른쪽 위 참가자 목록에 두 사용자가 표시되는지 확인한다.
5. 사용자별 이름과 색상으로 구분된 커서가 서로 보이는지 확인한다.
6. 화면의 연결 상태가 `실시간 동기화됨`인지 확인한다.

#### 회의 화면으로 복귀

1. 문서 수정이 두 브라우저에 동일하게 반영된 것을 확인한다.
2. PiP 창을 닫는다.
3. 기존 회의 화면으로 돌아가는 것을 확인한다.

#### 정상 확인

- 새 문서는 생성 즉시 편집 화면으로 열린다.
- 제목과 본문이 별도의 저장 버튼 없이 양쪽 화면에 동기화된다.
- 현재 참여 중인 사용자와 사용자별 커서가 표시된다.
- 새로고침 후에도 같은 내용이 유지된다.
- OWNER와 MEMBER는 편집할 수 있으며 GUEST는 읽기 전용이다.

#### 발표 설명 예시

> 회의 연결을 유지한 채 공유 문서를 열 수 있습니다. 문서 편집은 Tiptap과 Yjs CRDT를 사용해 실시간으로 병합되며, 접속 사용자와 사용자별 커서를 확인할 수 있습니다.

### 3.7 회의 종료

#### 종료 전 발화 예시

AI 산출물이 의미 있게 생성되도록 두 사용자가 최소 수십 초 이상 번갈아 발화한다.

```text
OWNER: 오늘 회의에서는 MVP 기능 범위를 확정하겠습니다.
MEMBER: 회원 인증, 팀 협업, 실시간 문서와 AI 회의록을 우선 구현하겠습니다.
OWNER: 공유 문서 동시 편집 검증은 MEMBER가 담당합니다.
MEMBER: AI 산출물과 다운로드 검증은 OWNER가 담당하고 다음 회의 전까지 완료하겠습니다.
OWNER: 오늘 결정사항은 문서에 반영하고 회의를 종료하겠습니다.
```

#### 실행 순서

1. 브라우저 A에서 VAD 업로드가 진행 중이라면 완료될 때까지 잠시 기다린다.
2. 회의 화면 아래 오른쪽의 빨간 수화기 버튼을 클릭한다.
   - 호스트에게는 접근성 이름 `회의 종료`로 제공된다.
3. `회의를 종료하면 모든 참가자의 연결이 종료됩니다. 계속할까요?` 확인 창에서 `확인`을 클릭한다.
4. 브라우저 B의 연결도 함께 종료되는 것을 확인한다.

#### 정상 확인

- OWNER와 MEMBER가 팀 스페이스의 `일정` 화면으로 이동한다.
- 종료한 회의가 `진행 중인 회의`에서 사라진다.
- 서버는 남은 VAD 업로드를 기다린 뒤 AI 회의 처리 작업을 비동기로 등록한다.

#### 발표 설명 예시

> 호스트만 전체 회의를 종료할 수 있습니다. 종료 시 남아 있는 음성 업로드를 정리하고 AI 처리를 비동기로 요청하므로 사용자는 긴 분석 작업이 끝날 때까지 회의 화면에서 기다릴 필요가 없습니다.

### 3.8 AI 산출물 확인

AI 처리는 음성 길이와 서버 상태에 따라 시간이 걸린다. 결과가 바로 보이지 않으면 30초~1분 간격으로 해당 메뉴를 다시 클릭하거나 화면을 새로고침한다.

#### 회의 전문 확인

1. 팀 왼쪽 메뉴의 `회의록`을 클릭한다.
2. `MVP 기능 검토 회의` 결과 행에서 `열기 →`를 클릭한다.
3. 발화자, 시작·종료 시각, 전사 문장이 표시되는지 확인한다.
4. 필요하면 `MD 내보내기` 또는 `PDF 내보내기`를 클릭한다.

화면의 `회의록` 메뉴는 API의 음성 전사 결과를 보여주는 영역이다.

#### AI 요약 확인 및 확정

1. 왼쪽 메뉴의 `AI 요약`을 클릭한다.
2. 해당 회의 행의 `열기 →`를 클릭한다.
3. 제목, 전체 요약, 주요 안건, 결정사항, 액션 아이템, 미해결 이슈를 확인한다.
4. `검토 및 수정 가능` 상태에서 필요한 내용을 수정한다.
5. `수정 내용 저장`을 클릭한다.
6. `최종 확정`을 클릭한다.
7. `AI 요약을 최종 확정하면 더 이상 수정할 수 없습니다. 확정하시겠습니까?`에서 확인한다.
8. 상태가 `최종 확정`으로 바뀌는지 확인한다.
9. `MD 내보내기`와 `PDF 내보내기`를 각각 클릭해 다운로드 URL이 열리는지 확인한다.

확정 전 AI 요약은 내보낼 수 없으며 최종 확정 후에는 다시 수정할 수 없다.

#### AI 피드백 확인

1. 왼쪽 메뉴의 `AI 피드백`을 클릭한다.
2. 해당 회의 행의 `열기 →`를 클릭한다.
3. 다음 항목을 확인한다.
   - 회의 종합 평가
   - 참여도와 참여자별 통계
   - 잘된 점과 개선할 점
   - 의사결정 과정 점검
   - 미해결 이슈 평가
   - 다음 회의 제안
4. `마크다운 내보내기` 또는 `PDF 내보내기`를 클릭한다.

#### 정상 확인

- 한 회의 ID를 기준으로 전사, AI 요약, AI 피드백이 모두 조회된다.
- AI 요약 수정과 최종 확정이 정상 반영된다.
- MD/PDF 내보내기 시 새 창 또는 다운로드가 시작된다.
- 비공개 S3 객체 자체가 아니라 Backend가 발급한 제한 시간 Presigned URL을 통해 파일에 접근한다.

#### 발표 설명 예시

> AI는 회의 음성을 전사하고 주요 안건, 결정사항과 액션 아이템을 구조화합니다. 사용자는 결과를 검토하고 수정한 뒤 확정할 수 있으며, 회의 진행 품질에 대한 퍼실리테이터 피드백과 MD·PDF 결과물도 제공합니다.

## 5. 시연 중 문제 대응

| 상황 | 확인 및 대응 |
| --- | --- |
| 회원가입 이메일 중복 | 날짜나 회차가 포함된 새 이메일 사용 |
| 로그인 후 온보딩 표시 | `나중에 하기`를 눌러 홈으로 이동 |
| 초대 검색 결과 없음 | MEMBER가 사전에 가입됐는지 확인하고 이메일 두 글자 이상 입력 후 결과 선택 |
| 초대 알림이 바로 보이지 않음 | 알림 패널의 `새로고침` 클릭 또는 페이지 새로고침 |
| 회의 입장 실패 | 브라우저 권한, LiveKit 상태, Backend 인증 세션 확인 |
| 마이크·카메라가 나오지 않음 | 주소창 사이트 설정에서 권한 허용 후 다시 입장 |
| 문서 PiP가 열리지 않음 | Chrome 사용, PiP 지원 및 권한 확인 |
| 문서가 읽기 전용 | 사용자가 OWNER 또는 MEMBER인지 확인 |
| 사용자 커서가 보이지 않음 | 두 사용자가 같은 문서 ID를 열었는지, 상태가 `실시간 동기화됨`인지 확인 |
| 회의 종료 버튼이 나가기로 동작 | 현재 사용자가 회의 호스트인지 확인 |
| AI 결과가 바로 나타나지 않음 | 비동기 처리 대기 후 메뉴 재진입 또는 새로고침 |
| AI 결과가 계속 생성되지 않음 | 실제 발화와 VAD 업로드 여부, AI Task 상태, Backend·AI 로그 확인 |
| AI 요약 내보내기 실패 | 먼저 `최종 확정`을 수행했는지 확인 |
| MD/PDF 링크가 열리지 않음 | 팝업 차단 해제, Backend S3 권한 및 Presigned URL 발급 상태 확인 |

## 6. 안정적인 발표를 위한 예비안

실시간 AI 처리는 음성 길이와 서버 부하에 영향을 받는다. 발표 직전에 같은 팀 스페이스에서 전사, 요약, 피드백 생성이 끝난 예비 회의 한 건을 준비한다.

라이브 회의 종료 후 결과가 발표 시간 안에 생성되지 않으면 다음과 같이 설명하고 예비 회의 결과로 전환한다.

> 회의 종료 요청과 AI 처리는 비동기로 분리되어 있습니다. 현재 방금 종료한 회의는 백그라운드에서 처리 중이므로, 동일한 흐름으로 미리 생성해 둔 회의의 결과를 보여드리겠습니다.

예비 회의도 반드시 실제 운영 계정과 팀 권한으로 접근 가능한 데이터여야 하며, 발표 전에 다음 항목을 확인한다.

- 회의 전문 목록과 상세 조회
- AI 요약 수정 가능 상태 또는 시연용 확정 상태
- AI 피드백 상세 조회
- MD/PDF 내보내기
- Presigned URL 만료 전 재발급 동작

## 7. 시연 종료 후 정리

- 시연용 계정, 팀 스페이스와 회의를 운영 데이터로 계속 사용할지 결정한다.
- 불필요한 시연 데이터는 서비스의 정상 삭제 기능으로 정리한다.
- 브라우저 B의 시크릿 창을 닫아 세션을 종료한다.
- 다운로드한 AI 산출물에 민감한 발화 내용이 있다면 안전하게 삭제한다.
- 발표 중 실제 Secret, AWS Console 자격 증명, DB 접속 정보나 개발자 도구의 인증 토큰을 화면에 노출하지 않는다.
