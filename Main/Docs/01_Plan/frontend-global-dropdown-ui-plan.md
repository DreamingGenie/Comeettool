# 전역 Dropdown UI 통일 계획

## 목표

- 앱 전체의 dropdown과 선택 입력을 참고 이미지처럼 부드럽고 둥근 카드 형태로 통일한다.
- 기능별로 제각각인 높이, 테두리, 글자 크기, hover·focus 상태를 정리한다.

## 적용 범위

### 네이티브 선택 입력

- 새 회의 스페이스 선택
- 문서 정렬
- 프로필 연령대·직군·세부 직무
- 회의록·AI 자료 정렬
- 팀 기본 권한 및 소유권 이전
- 멤버 권한 및 직무 선택

### 커스텀 Dropdown

- 사용자 검색 결과
- 워크스페이스 컨텍스트 메뉴
- 알림 목록 등 선택형 팝오버

## 디자인 기준

- 입력창 및 버튼 모서리: `12px`
- 펼쳐지는 패널 모서리: `14px`
- 패널 내부 선택 항목 모서리: `10px~12px`
- 외곽선: `#cfd6e6` 계열
- 패널 배경: 흰색
- 선택 항목 기본 배경: `#f5f6fb`
- hover 배경: `#eceffd`
- focus ring: 옅은 블루 퍼플
- 입력 글자: `13px~14px`
- 보조 정보: `11px~12px`
- 그림자: 넓고 옅은 블루 그레이

## 구현 방법

1. 전역 CSS에 공통 `<select>` 외형 규칙을 추가한다.
2. 각 화면의 중복된 select 스타일은 크기·레이아웃만 남기고 색상과 모서리는 공통 규칙을 따른다.
3. 커스텀 dropdown 패널에 동일한 테두리·모서리·그림자 토큰을 적용한다.
4. disabled, hover, focus-visible 상태를 통일한다.
5. 기존 `v-model`, change 이벤트, API 요청 로직은 변경하지 않는다.

## 제한 사항

- 네이티브 `<select>`를 클릭한 뒤 나타나는 운영체제 옵션 목록은 브라우저가 렌더링하므로 모서리와 행 디자인을 완전히 제어할 수 없다.
- 펼쳐진 옵션 목록까지 참고 이미지와 완전히 동일하게 만들려면 추후 공통 커스텀 Select 컴포넌트로 교체해야 한다.
- 이번 작업은 기능 안정성을 위해 네이티브 select 동작을 유지하고, 닫힌 선택창과 앱이 직접 렌더링하는 dropdown 패널을 통일한다.

## 검증

1. 각 화면의 select 높이·모서리·폰트 일관성 확인
2. dropdown이 화면 밖으로 넘치거나 잘리지 않는지 확인
3. 키보드 focus와 disabled 상태 확인
4. 기존 정렬·권한·프로필 선택 기능 회귀 테스트
5. 프론트엔드 빌드 확인
